## Summary

**Goal:** Убрать «редактирование вслепую» из /admin/cms: вместо девяти плоских аккордеонов — дерево «Страница → Секция → Поля» с iframe-предпросмотром рядом, бейджами «изменено» (значение ≠ дефолту схемы), сбросом к дефолту и вычищенными legacy-дублями. Ноль миграций схемы БД; этап 1 из трёх (консультация 2026-07-06, память: project_cms_restructure_plan.md). Оценка: **3–4 дня** (critic M4: бейдж-компаратор и state-синхронизация — реальная работа, а не каветы).

## Out of Scope

- Этап 2 (секции как данные / page-builder, draftMode, ревизии) и этап 3 (Payload CMS) — отдельные инициативы; этап 1 лишь закладывает совместимую структуру (дерево выводится из ключей, не хардкодится).
- Черновики и история изменений — «изменения применяются сразу» остаётся (этап 2).
- Разделение «контент vs настройки организации» на уровне данных — в UI дерево уже разводит их по разным верхнеуровневым узлам («Страницы» / «Организация»), но ключи и хранение не переезжают.
- Мобильная вёрстка предпросмотра — iframe-панель скрывается на узких экранах, адаптивный сплит не строим.

## Approach

**Chosen:** Чистая переупаковка UI поверх существующего контракта — `CMS_SCHEMA`/`CMSBlock`/редакторы полей (`components/admin/cms/*`) и save-контекст не меняются; добавляется производный слой `lib/cms-tree.ts` (страница → секции из второго сегмента ключа) и новый трёхпанельный layout страницы `/admin/cms` (дерево · поля секции · iframe-предпросмотр).
**Why:** Иерархия уже закодирована в именах ключей (`home.hero.left.title`) — её нужно показать, а не пересоздать; это даёт «не-вслепую» редактирование за 1–2 дня без единой миграции и без риска для публичного рендера. Цена: URL-состояние и iframe-синхронизация — чисто клиентская логика админки.

## Context for Implementer

Схема — единственный источник правды: 86 ключей в `lib/cms-schema.ts` (тип text/richtext/list/image, group из 9 значений, label, defaultValue). Значения читаются из `CMSBlock` (JSON `content`) с фолбэком на дефолты через `lib/cms.ts` (`getCMSText/…Richtext/…List/…Image`). **КРИТИЧНО (critic C1, проверено эмпирически): `prisma/seed.ts` upsert'ит ВСЕ ключи схемы — в dev-БД 86/86 строк, поэтому «переопределено» НЕЛЬЗЯ определять как «строка существует»; определение: сохранённое значение ≠ `defaultValue` схемы (посравнение по типу: строка для text/richtext/image, deep-equal для list), вычисляется СЕРВЕРНО в page.tsx и передаётся вниз готовым `Set<key>`.** Редакторы полей и `CMSSaveContext` (`components/admin/cms/*`) переиспользуются как есть — меняется только группировка/навигация вокруг них; известная ловушка: редакторы держат значение в `useState(initial)` без синхронизации — «сброс» обязан ремаунтить редактор через `key={\`${cmsKey}:${resetVersion}\`}` на обёртке. Ключи двухсегментные (`about.title`) не имеют секции — попадают в бакет «Общее» своей страницы. Публичные страницы: home → `/`, about → `/about`, services → `/services`, contacts → `/contacts`, vacancies → `/vacancies`; группы footer/fab/cookie — сквозные (предпросмотр на `/`), requisites — без предпросмотра (узел «Организация»).

## Assumptions

- Iframe same-origin (админка и публичные страницы на одном хосте); публичные роуты не требуют auth. — Tasks 3–4 depend on this.
- `home.hero.title` / `home.hero.subtitle` нигде не читаются (grep: только `home.hero.image` используется в `app/(public)/page.tsx:70`) — Task 2 depends on this; re-verify before deletion.
- Компаратор «значение ≠ дефолт» делает состояние бейджей корректным независимо от того, полностью ли prod-БД засеяна (dev: 86/86 строк) — открытый вопрос критика о частичном prod-сиде становится нерелевантным. — Task 3 depends on this.
- В предпросмотре рендерится полный хром публичной страницы (sticky Header, FAB, cookie-баннер); cookie-баннер закрывается один раз — согласие живёт в same-origin localStorage. Принято как норма, не баг.

## Implementation Tasks

### Task 1: lib/cms-tree.ts — производное дерево + тесты

**Objective:** Чистый модуль, выводящий из `CMS_SCHEMA` структуру навигации: два корня («Страницы» — home/about/services/contacts/vacancies + сквозные footer/fab/cookie; «Организация» — requisites), внутри страницы — секции по второму сегменту ключа в порядке первого появления в схеме, двухсегментные ключи — в секцию «Общее». Секции получают русские подписи из небольшой карты `SECTION_LABELS` (hero → «Хиро-блок», stats → «Цифры», whyus → «Почему мы», faq → «FAQ», reviews → «Отзывы», cta → «Призыв к действию», …) с фолбэком на сам сегмент. Verified by unit tests.

**Files:**

- Create: `lib/cms-tree.ts`
- Test: `tests/cms/cms-tree.test.ts`

**Key Decisions / Notes:**

- Функция `buildCmsTree(schema)` принимает схему параметром (тестируется на фикстурной мини-схеме, не на живых ключах), плюс экспорт `CMS_TREE` на реальной схеме.
- Метаданные страниц: `{ group, label (из GROUP_LABELS), previewPath | null }`; сквозные группы получают `previewPath: "/"`, requisites — `null`.
- Секция «Общее» (двухсегментные ключи) идёт ПЕРВОЙ в списке секций страницы (critic minor: неопределённый порядок ронял её в середину списка).
- Ключи-«родители и дети» одновременно (`home.stats.years` И `home.stats.years.label`) — оба ПЛОСКИЕ листья секции `stats` по второму сегменту; префиксного дерева НЕ строить. Явный юнит-тест на этот кейс (critic minor).
- `SECTION_LABELS` должен разводить коллизии имён секций с именами страниц (например, сегмент `footer` внутри страницы) — подписи секций всегда со своей карты, не из GROUP_LABELS.
- Никаких изменений в `lib/cms-schema.ts`, кроме Task 2.

**Definition of Done:**

- [ ] Дерево для реальной схемы: у «Главной» ровно секции hero/stats/whyus/faq/reviews/cta (+«Общее» при наличии), КАЖДЫЙ ключ схемы попадает ровно в одну секцию (сумма по секциям = числу ключей схемы — не хардкодить 86/84, счётчик плавает после Task 2).
- [ ] Порядок: «Общее» первым, далее секции в порядке первого появления в схеме; тест на префикс-коллизию `years`/`years.label` зелёный.
- [ ] Verify: `npx vitest run tests/cms/cms-tree.test.ts`

### Task 3: Трёхпанельный layout /admin/cms

**Objective:** Заменить колонку аккордеонов трёхпанельным экраном: слева дерево (страницы → секции, счётчик изменённых полей на узлах), в центре поля выбранной секции (существующие редакторы + save-контекст), справа сворачиваемый iframe-предпросмотр страницы с перезагрузкой после сохранения. Бейдж «изменено» у переопределённых полей и кнопка «Сбросить к дефолту» (server action удаляет строку CMSBlock). Verified by TS-001/TS-002/TS-003.

**Files:**

- Modify: `app/(admin)/admin/cms/page.tsx` (загрузка values как сейчас + разметка трёх панелей; выбранные page/section — из `searchParams` `?page=&section=`, дефолт — первая секция «Главной»)
- Create: `components/admin/cms/CMSTreeNav.tsx` (клиентское дерево; ссылки меняют searchParams; счётчики «изменено» по данным values)
- Create: `components/admin/cms/CMSSectionPanel.tsx` (поля секции — переиспользует CMSTextEditor/…Richtext/…List/…Image и CMSSaveSectionProvider; на каждом поле бейдж «изменено» + «сбросить»)
- Create: `components/admin/cms/CMSPreviewPane.tsx` (iframe `previewPath`; ref + перезагрузка по событию сохранения из save-контекста; кнопка «скрыть предпросмотр»; для `previewPath: null` — заглушка «нет предпросмотра»)
- Modify: `components/admin/cms/CMSSaveContext.tsx` (колбэк/событие onSaved для перезагрузки iframe — минимальное расширение)
- Modify: `app/actions/cms.ts` (новый action `resetCMSBlock(key)` — ADMIN/MANAGER, `delete` строки, revalidate)
- Delete/absorb: `components/admin/cms/CMSGroupSection.tsx` (его читалки значений переезжают в CMSSectionPanel; аккордеон умирает)

**Key Decisions / Notes:**

- URL — единственный источник выбранного узла (шэрабельные ссылки, как в фильтрах заказов).
- **«Изменено» (critic C1):** сохранённое значение ≠ `defaultValue` схемы — НЕ существование строки (сид создаёт все строки!). Сравнение по типу (string / deep-equal для list) выполняется СЕРВЕРНО в page.tsx → готовый `overriddenKeys: Set<string>` передаётся в дерево и панель; на клиенте deep-equal не гоняется.
- **Сброс (critic M1):** редакторы держат `useState(initial)` без ресинка — «сбросить к дефолту» ремаунтит поле через `key={\`${cmsKey}:${resetVersion}\`}` на обёртке (пропсы editors не меняются — ограничение соблюдено). Несохранённые правки поля при сбросе ТЕРЯЮТСЯ — кнопка armed-confirm в два клика («Сбросить? / Да, к дефолту»), как DeleteSupplierOrderButton.
- **Синхронизация после save/reset (critic M2):** `updateCMSBlock` ревалидирует только публичные страницы — серверные `overriddenKeys`/счётчики дерева сами не обновятся; в onSaved-колбэк save-контекста добавить `router.refresh()` (и после reset), затем перезагрузка iframe.
- Iframe получает `?cms-preview=1` в query — публичные страницы игнорируют, но это даёт задел для этапа 2 (draftMode) без переделки.
- Существующие editors не переименовывать и не менять их пропсы — только новая обёртка.

**Definition of Done:**

- [ ] TS-001, TS-002, TS-003 проходят в браузере.
- [ ] Все ключи схемы доступны через дерево (сумма полей по секциям = числу ключей схемы).
- [ ] Свежезасеянное нетронутое поле НЕ несёт бейджа «изменено»; поле с реально изменённым значением — несёт; после сброса бейдж исчезает без ручного F5 (router.refresh).
- [ ] `npm run build` зелёный; никакой правки публичного рендера в этой задаче.
- [ ] Verify: `npm test && npm run build` + браузерный прогон TS-001…003
